# AI-дайджест — Telegram-бот

## Что это

Раз в неделю бот собирает новости об AI из 9 источников (RSS-ленты и два Telegram-канала), отбирает до 25 самых свежих и присылает дайджест одним или несколькими сообщениями в личный чат владельца. Запускается по расписанию в GitHub Actions, историю отправленных ссылок хранит в SQLite-файле `digest.db`.

## Как устроено

Цепочка шагов (`pipeline.py`):

1. **Сбор** — RSS через `feedparser`, Telegram-каналы через `Telethon`; у ссылок убираются utm-метки и прочий мусор.
2. **Удаление повторов** внутри одного сбора (одна и та же ссылка из разных источников).
3. **Фильтр по дате** — только новости за последние 7 дней.
4. **«Уже отправлено»** — отсев ссылок, которые есть в `digest.db`.
5. **Отбор по темам** — до 25 новостей, темы чередуются по кругу, внутри темы сначала свежие.
6. **Сборка** — вступление, разделы по темам, нарезка на части до 4096 символов.
7. **Отправка частями** через Bot API.
8. **Запись в базу** — новости каждой части помечаются отправленными сразу после доставки этой части.

## Запуск локально

Нужен Python 3.12. Команды для Git Bash на Windows:

```bash
py -3.12 -m venv venv
source venv/Scripts/activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env        # затем впишите значения в .env
python main.py --dry-run    # предпросмотр: печатает дайджест; ничего не отправляет, digest.db не меняется
python main.py              # настоящий запуск: отправляет дайджест в Telegram
```

Файл `.env` в репозиторий не попадает.

## Переменные окружения

| Переменная | Назначение | Где взять |
|---|---|---|
| `BOT_TOKEN` | Токен бота, от имени которого уходят сообщения | @BotFather в Telegram |
| `OWNER_CHAT_ID` | Идентификатор чата, куда приходит дайджест | Ваш chat_id в Telegram |
| `TG_API_ID` | Идентификатор приложения Telegram для Telethon | my.telegram.org → API development tools |
| `TG_API_HASH` | Ключ приложения Telegram для Telethon | my.telegram.org → API development tools |
| `TG_SESSION` | Строка сессии личного аккаунта для чтения каналов | `python generate_session_string.py` (потребует номер телефона и код из Telegram) |

Без любой из них `main.py` сообщит, чего не хватает, и завершится с ошибкой.

## GitHub Actions

**Секреты.** В репозитории: Settings → Secrets and variables → Actions → New repository secret. Нужны пять: `BOT_TOKEN`, `OWNER_CHAT_ID`, `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`.

**Расписание.**

- Основной запуск (`weekly_digest.yml`) — каждый понедельник в 07:17 по Стамбулу (`17 4 * * 1` по UTC).
- Сторожевая проверка (`watchdog.yml`) — каждый понедельник в 12:23 по Стамбулу (`23 9 * * 1` по UTC). Считает только запуски по расписанию: ручной запуск не скрывает пропущенный плановый.

**Ручной запуск.** Вкладка Actions → выбрать workflow → Run workflow. У основного workflow есть галочка `dry_run`: с ней дайджест только печатается в логе запуска и в Telegram не уходит.

**База.** После каждого запуска workflow коммитит обновлённый `digest.db` обратно в репозиторий, поэтому история отправленного сохраняется между запусками.

## Уведомления

| Что случилось | Как узнаете |
|---|---|
| Запуск упал | Письмо от GitHub и сообщение бота об ошибке (с числом уже отправленных частей, например «Отправлено частей: 1 из 3») |
| Один источник не ответил | Предупреждение «⚠️ Без новостей (ошибка сбора): …» в начале дайджеста; остальные источники работают как обычно |
| Плановый запуск не состоялся (GitHub не стартовал workflow по расписанию) | Сообщение от watchdog в 12:23: «Дайджест сегодня не запускался» |

## Как добавить источник

Добавьте запись в `sources.yaml`:

```yaml
- name: Example Blog
  url: https://example.com/feed.xml
  type: rss                       # rss или telegram
  topics: [AI-агенты, AI-инструменты]
  language: en
  enabled: true
  keywords: [agent, llm]          # необязательно: брать только записи с такими словами в заголовке
```

Как назначается тема:

- Если у источника одна тема, её получают все его новости.
- Если тем несколько, тема выбирается по ключевым словам из `topics.yaml`. Сначала слова ищутся в заголовке, затем в тексте новости; темы перебираются в том порядке, в каком они перечислены у источника; побеждает первая с совпадением. Слово должно начинаться с ключа (ключ `агент` найдёт «агента» и «агентов»), регистр не важен. Если совпадений нет, берётся первая тема источника.
- Поле `keywords` у источника — другое: оно отбирает, какие записи вообще брать.

Для Telegram-канала укажите `type: telegram` и `url: https://t.me/<канал>`.
